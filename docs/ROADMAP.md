# MyHarbor 迭代路线图

## 1. 目标与原则

- 目标：在 4 个迭代内交付可用、可部署、可运维的 MyHarbor v1。
- 原则：先核心闭环（浏览 + 管理 + 检测），再增强能力（统计 + 备份恢复 + 运维）。

## 2. 里程碑计划

| 里程碑 | 时间窗口（建议） | 目标 | 关键产出 |
|------|------|------|------|
| M1 基础框架 | 2026-02-17 ~ 2026-02-23 | 跑通前后端与数据库骨架 | 项目脚手架、数据模型、公开接口 |
| M2 管理后台 | 2026-02-24 ~ 2026-03-02 | 完成后台登录与站点管理 | JWT 登录、站点 CRUD、系统设置 |
| M3 监控与统计 | 2026-03-03 ~ 2026-03-09 | 完成状态检测与访问统计 | 定时任务、状态图例、统计面板 |
| M4 交付与运维 | 2026-03-10 ~ 2026-03-16 | 完成部署与运维能力 | Docker 交付、备份恢复、CLI、文档完善 |

## 3. 里程碑验收标准

### 3.1 M1 验收

- 前台首页可展示公开站点并支持标签筛选、搜索。
- 数据库自动初始化默认配置。
- 公开 API 可被前端联调调用。

### 3.2 M2 验收

- 管理员可登录并维持 24 小时会话。
- 站点支持增删改查、公开状态切换、排序更新。
- 后台安全路由码可修改，修改后旧路径失效。

### 3.3 M3 验收

- 可手动/定时检测站点状态，日志保留 30 天。
- 可记录访问日志并生成日/月/年/总计统计。
- 管理端可查看 30 天状态图例与趋势图。

### 3.4 M4 验收

- Docker Compose 一键启动可用。
- 支持备份导出与导入（skip/overwrite）。
- `manage.py` 支持凭证恢复命令。
- 核心用例通过率 >= 95%。

## 4. 风险与应对

| 风险 | 影响 | 应对 |
|------|------|------|
| SQLite 写入竞争 | 检测与统计任务冲突 | WAL 模式 + 任务错峰 + 事务控制 |
| 登录暴力尝试 | 账户安全风险 | 限流 + 错误日志审计 + 强制改默认密码 |
| 导入脏数据 | 数据污染 | JSON Schema 校验 + 失败回滚 |
| 单实例调度限制 | 多实例行为不一致 | v1 单实例部署，v2 再引入集中调度 |

## 5. 版本发布建议

- `v0.1.0`：完成 M1
- `v0.2.0`：完成 M2
- `v0.3.0`：完成 M3
- `v1.0.0`：完成 M4 并验收通过
